What Zumly is

Zumly is a JavaScript library for zoom navigation, also called a zooming user interface (ZUI). Your interface is a set of screens called views. Clicking an element zooms into it, and the next view grows out of that element. Zooming out goes back the same way.

It is not an infinite pan-and-zoom canvas like a map or a whiteboard. Movement happens in steps, through the elements you mark as triggers, and each view loads only when it is needed. You write the HTML and CSS; Zumly computes and animates the transforms.

ZumlyPan-and-zoom canvas
MovesIn steps, from a trigger to its viewFreely, to any point and scale
ContentSeparate views, loaded on demandOne large surface
Good forDashboards, drill-downs, menus, kiosks, configuratorsMaps, whiteboards, diagrams

It is a poor fit for long reading flows and plain forms, where there is nothing to zoom into.

How it works

Think of your app as screens, not as one big canvas. Each screen is a view you write by hand, with its own HTML and CSS. Inside a view, you mark some elements as triggers: a card, a circle, a letter.

When someone clicks a trigger, Zumly does the rest. It scales the current view up until the trigger fills the screen, and the next view grows out of that spot. The view you came from stays behind, dimmed, so you still see where you are.

Going back is the same trip in reverse: the current view shrinks back into the trigger, and the parent comes back into focus. Moving between siblings slides sideways instead.

The trick is a convention, not magic. If the trigger and the view it opens share a shape, the zoom feels real. If they look different, it still works, it just reads as a morph. You decide what each screen looks like. Zumly decides how to get from one to the other.

Most of that trip can be tuned. How long it takes and with what curve. Whether the trigger covers the new view by width or by height when their shapes differ. What happens to the views behind, from a soft blur to nothing at all. Which engine draws it: CSS, GSAP, WebGL. You can set these once for the whole app, or per trigger with data-with-* attributes. The defaults are there so you don't have to think about any of it on day one.

Why Zumly

  • Zoom from the element. The next screen grows out of what you clicked and shrinks back into it, so you always know where you came from.
  • Context stays. The screens you came from wait behind the current one, dimmed. Click one, scroll, swipe or press ← to go back.
  • Depth and siblings. A back button at every level (it can show the parent's name or jump several levels), arrows and swipe between siblings, and browser history with the router.
  • Gestures. Pinch, swipe or the trackpad drive the zoom-out as you move. Let go past the middle and it finishes; otherwise it goes back.
  • Any animation engine. CSS by default, or Web Animations, GSAP, Anime.js, Motion or a driver of your own. The same ease gives the same curve on all of them.
  • Your views, your framework. HTML strings, URLs, functions, or React, Vue, Svelte and Angular components. No dependencies.
  • Accessible. Keyboard, focus and screen-reader labels work out of the box.
