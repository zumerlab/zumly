Navigation controls

Zumly draws two controls for you: a back button that zooms out and a sibling bar that moves sideways. Change any option below and the example rebuilds on the view you were on.

The back button

It appears from the first level down and zooms out one level. A view that brings its own element with class z-depth-nav replaces it.

OptionValuesDescription
style'button' (default), 'title', 'rings'A dot in its ring; the same plus the title of the view above; or a ring per level above. With 'rings', hover, a long press or ArrowUp opens a band per level to jump several at once.
position'bottom-left' (default), 'top-left'Its corner.

depthNav: false removes it. Clicking the dimmed parent, the wheel, a swipe left and ArrowLeft still zoom out.

The sibling bar

It appears when the current view has siblings: the views of the other triggers in its parent. Each level has its own group, so the bar changes as you zoom in and out. Step 3 explains who counts as a sibling.

OptionValuesDescription
position'bottom-center' (default), 'top-center'Its edge.
mode'always' (default), 'auto''auto' hides the bar on views that cover the whole canvas.
arrows, dotstrue (default), falseWhich parts to draw.
swipefalse (default), trueA horizontal swipe moves between siblings. Where there are none, a swipe left still zooms out.
keepAlivefalse (default), true, 'visible'Siblings you leave stay in the DOM (hidden, or visible behind), so their state survives while you stay at that level.
siblings{ parent: [names] }The order per parent view, instead of the order of the triggers.

Triggers that share a view and differ in their data (data-to="room" data-id="kitchen") are separate siblings, each with its own dot named by its data-title. To keep a trigger out of the group, mark it data-sibling="false". lateralNav: false removes the bar; the siblings are still there for goTo(name, { mode: 'lateral' }).

When they share an edge

Put both at the bottom (or both at the top) and the bar moves aside to leave room for the button. On a narrow screen with no room beside it, the bar goes above the button. Try position in the example on a phone-sized window.

Restyle them

Both controls share one frosted look. Set these custom properties on the canvas, or on .z-depth-nav or .z-lateral-nav for just one:

.canvas {
  --z-nav-bg: rgba(255, 255, 255, 0.7);   /* background */
  --z-nav-color: #0b2a44;                 /* glyphs, rings, arrows, dots */
  --z-nav-active: #3da9fc;                /* current dot */
  --z-nav-border: transparent;
  --z-nav-shadow: none;
  --z-nav-blur: blur(10px);               /* its backdrop-filter */
  --z-nav-hover: rgba(0, 0, 0, 0.06);
}

Their words

Screen readers read the labels below. {title} is the view's data-title. Each one can be a template, a function ({ name, title }) => string, or false.

labels: {
  back: 'Volver a {title}',
  prev: 'Anterior',
  next: 'Siguiente',
  goTo: 'Ir a {title}'
}

Build your own

Turn both off and drive your own buttons with the same methods the built-in controls use:

const app = new Zumly({ ..., depthNav: false, lateralNav: false })

app.on('viewChanged', () => {
  backButton.hidden = !app.canGoBack()
  crumbs.textContent = app.getViewStack().map(view => view.title).join(' › ')
})

backButton.onclick = () => app.zoomOut()        // one level up
homeButton.onclick = () => app.zoomOut({ to: 'ocean' })   // several levels, one transition
nextButton.onclick = () => app.goTo('midnight', { mode: 'lateral' })

back() is the other choice for a back button: it undoes sideways moves at the current level before zooming out, like the browser back button with the router.
