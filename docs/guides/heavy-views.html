Heavy views

A view with thousands of nodes, or with frosted glass, is costly to scale and blur on every frame. flatten takes a photo of each view while you are in it, with SnapDOM, and moves the photo while the view sits behind. Zoom into a bright tile with it on, then off.

Live exampleOpen ↗

Turn it on

Install SnapDOM next to Zumly and hand it over:

npm install zumly @zumer/snapdom
import Zumly from 'zumly'
import { snapdom } from '@zumer/snapdom'

new Zumly({ mount: '.canvas', initialView: 'home', views, flatten: { snapdom } })

With script tags, load SnapDOM before Zumly and pass flatten: true, which reads the global snapdom:

<script src="https://unpkg.com/@zumer/snapdom/dist/snapdom.js"></script>
<script src="https://unpkg.com/zumly/dist/zumly.js"></script>

Zumly does not depend on SnapDOM. If it is missing, Zumly says so once in the console and the views stay as they are.

What happens

  • You arrive at a view and stop for a moment: Zumly takes its photo, a little at a time, so taps and drags still answer.
  • You zoom into something: the view you leave shows the photo. Its content is still there and laid out, only hidden, so the blur and dimming, clicks on siblings and every driver work as before.
  • You come back: the real view returns, crossfading from the photo.
  • You leave before the photo is ready: that zoom moves the real view. Nothing waits for a photo.

When it pays off

Three zooms in and three out, with a clock, spinners and numbers changing in every view. Chrome on a MacBook; a dropped frame is one the screen never got.

ViewsWithoutanimateEffects: falseWith flatten

A light view gains nothing, so flatten leaves it alone. It photographs a view with at least minNodes elements, or with backdrop-filter inside. Mark a view data-flatten="true" to photograph it anyway, or data-flatten="false" to keep it live behind (a video, a game). Views with an iframe stay live: SnapDOM can only draw a placeholder for it.

Options

OptionDefaultDescription
snapdomthe global snapdomThe snapdom function from @zumer/snapdom.
minNodes800Views with fewer elements are photographed only if they use backdrop-filter.
scale1Resolution of the photo. The blur behind hides its softness; without effects, 2 keeps text behind sharp, for four times the memory.
refreshfalseWith false, the photo is the view as you found it, plus what you change by hand. A number of milliseconds also follows changes nobody made by hand (live data), taking a new photo at most that often.

Good to know

  • The view behind stands still. A clock or a chart that updates stops while the view is behind, and is current again when you come back. Set refresh if the photo should follow it.
  • Change something by hand, a toggle or a slider, and leave at once: that view moves as itself until its new photo is ready, so its old state never flashes.
  • Each view behind keeps its photo in a canvas: width × height × 4 bytes, times the pixel ratio squared.
  • On a slow tablet a photo takes up to a second, spread over many frames. Zumly waits for a quiet moment to start one.

Try the cheap fix first

transitions: { animateEffects: false } applies the blur at once instead of animating it. It needs nothing else, and with many nodes it already takes out part of the stutter. Reach for flatten when that is not enough: frosted glass, thousands of nodes, or a slow device.
